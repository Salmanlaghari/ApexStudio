# Open-source patterns informing the editor follow-up

Research informed architecture and test ideas only. No third-party code, shaders, LUTs, presets or art were copied, and no dependencies were added. New filter recipes and shaders are authored here. The new small SDR instrumentation video derives only from this repository's existing synthetic fixture; its reproducible remux/metadata command is recorded beside it.

## Composition-wide grading and comparison

[Kdenlive's effects manual](https://docs.kdenlive.org/en/effects_and_filters.html) distinguishes effects on a source/bin clip (shared across its timeline instances), an individual timeline clip, a track, and the Master (all tracks). Its [Effects Everywhere guide](https://docs.kdenlive.org/en/tips_and_tricks/tips_and_tricks/effects_everywhere.html) documents effect zones for limiting track/master effects to timeline regions and a split before/after monitor for bin-clip effects. Important limitation: the documented split comparison is not available for track or Master effects. The [Lift/Gamma/Gain guide](https://docs.kdenlive.org/en/tips_and_tricks/how-tos/lift_gamma_gain.html) likewise documents on/off and movable split comparisons. Kdenlive application source is [GPL-3.0](https://github.com/KDE/kdenlive/blob/master/COPYING); its manual states [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/).

Applied here: range/strength/settings remain in immutable workspace data; preview/export effects share `WorkspaceEffectGlEffect.createEffects`; source-clock conversion is tested explicitly. The Color source-frame comparison remains explicitly source-only. Project timeline comparison instead renders the same frozen supported composition twice with only the new grade changed, validates their encoded frame clocks, and shares the exact compared After MP4. This avoids pretending a decoded source bitmap includes timeline text, trims or effects. **Not implemented:** arbitrary multitrack/master-grade composition support, live synchronized composition playback, or the reference editors' four-level effect UI and zone controls. Unsupported project content blocks rendering; Android-device behavior is still unverified here.

## Timeline, ranges, and text

[Shotcut's feature list](https://www.shotcut.org/features/) documents a native multitrack timeline, keyframed filters, an adjustment clip, timeline ranges/markers, range export, 3-way color wheels, rich text, and compositing. These are feature-level references, not a claim that every item is equivalent to this editor's project/range model. Shotcut source is [GPL-3.0](https://github.com/mltframework/shotcut/blob/master/COPYING).

Applied here: keep start, end, actual duration, and playhead distinct; clamp ranges to project duration; map logical text spans into clip-local render windows with export timeline math. [Kdenlive title clips](https://docs.kdenlive.org/en/titles_and_graphics/titles/titles.html) are ordinary alpha-bearing timeline clips that can be stacked, effected, and keyframed; this informed treating timed text as timeline content. The original editor layout remains. **Not implemented:** adjustment clips or a new lane/track UI patterned after other editors.

## Preview/export and paused-frame cautions

The official [Media3 composition guide](https://developer.android.com/media/media3/transformer/composition) covers per-item effects and sequential edited items. [CompositionPlayer](https://developer.android.com/media/media3/transformer/compositionplayer) can preview a Transformer composition, but is documented as experimental—not evidence this app already has complete composition preview. Media3's [primary license](https://github.com/androidx/media/blob/release/LICENSE) is Apache-2.0; Android docs prose is CC BY 4.0 and code samples Apache-2.0.

[Media3 issue #1393](https://github.com/androidx/media/issues/1393) discusses delayed effect replacement; [#2363](https://github.com/androidx/media/issues/2363) and [#2940](https://github.com/androidx/media/issues/2940) discuss paused redraw, mutable parameters, and frame replay. These are version-specific discussions, not proof of this app's bug or a universal fix. Applied here: separate model invalidation from Player binding and request a same-source-position refresh when a replacement chain is installed while paused and ready. Device playback and paused-frame behavior still need validation.

The [Material Slider guide](https://github.com/material-components/material-components-android/blob/master/docs/components/Slider.md) documents two-thumb range selection; Material Components' [license](https://github.com/material-components/material-components-android/blob/master/LICENSE) is Apache-2.0. [GPUVideo-android](https://github.com/MasayukiSuda/GPUVideo-android) illustrates separate filter preview and MP4 export paths; its [license](https://github.com/MasayukiSuda/GPUVideo-android/blob/master/LICENSE) is MIT. Both are comparative references, not imported implementations. Applied test principle: verify pixels and explicit effect/time settings rather than trusting matching UI labels; host GLES tests are not Android-device certification.
