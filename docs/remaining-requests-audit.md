## Validation limits and next checks

- This follow-up changes timeline/dashboard UI source, adds Compose regressions for those controls, and clarifies the FFmpeg dependency contract. Tests of callbacks and labels do not prove picker delivery, device visual quality, native codec behavior or preview/export parity.
- The combined validation commands are `python3 -m unittest discover -s scripts/tests`, `python3 scripts/verify-ai-models.py`, and `./gradlew :app:testDebugUnitTest :feature:camerakit:testDebugUnitTest :app:compileDebugAndroidTestKotlin`. See the PR for their final results; compiling instrumentation is not running it on a device.
- Target-device import timing, Cover/Fit behavior, enlarged preview appearance and rendered export comparisons still need Prince's device test. Social/authentication requirements, a generic Next route and all-category moderation remain incomplete rather than represented by dead buttons.

## Image-session provider compatibility

The new dashboard image route exposed a concrete metadata-path gap: generic photo/document providers may support `OpenableColumns.DISPLAY_NAME` but not MediaStore's video metadata columns. The old fallback then attempted to use `MediaMetadataRetriever` on a still image. Image MIME types now read dimensions from the provider stream using `BitmapFactory.Options.inJustDecodeBounds`, without decoding a full pixel buffer or using video metadata extraction; photo clips retain the existing 3000 ms default duration. Display-name lookup requests only the OpenableColumns contract and falls back to the URI segment/generated name. A Robolectric provider test serves a real PNG, rejects video-column projections and verifies name, dimensions, type and duration. Its focused run passed. This does not measure large-video import latency or prove every OEM/cloud photo provider works.

## Cover/Fit is not a new output setting

The existing top-bar Cover/Fit control changes a local preview viewport mode; the square crop preset is `1:1`, mathematically equivalent to `4:4`. This follow-up does not turn the preview viewport flag into a persisted export fit/crop setting, change the default preview size, or establish the requested visual/export parity. Those reported issues remain unvalidated, not declared fixed because a button and a source callback exist.
