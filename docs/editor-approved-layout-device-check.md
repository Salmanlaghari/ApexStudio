# Approved editor follow-up: what to test on your phone

This follow-up starts from merged PR #172 (`f4ce16d6621e368668ce9ab73ca0fe9213eaf219`). The owner's agreed, locked **51303.png** purple/cyan design is the visual authority. **51301.jpg is the rejected current-app screenshot, not a target.** An earlier local interpretation reversed these; it is superseded by this implementation. **Do not merge until the owner tests the exact supplied APK and explicitly approves.**

## Layout and real controls

The editor uses a deep navy canvas, branded gradient ApexStudio header, outlined resolution control and luminous cyan-to-purple Export. The normal timeline starts at its ruler, not a full-width TIMELINE/Add Clip header. Selected clips have purple/cyan emphasis; real text/sticker/FX/audio layers use the locked design's colored tracks. It remains content-bounded: no fabricated empty support lanes, identity/eye gutter or full-width SEC row. Keyframe markers stay centered in their real tracks.

The landscape editing canvas replaces the rejected tall black portrait frame. Source FIT behavior preserves footage without silently cropping it; fullscreen remains a full-window mode. Real text/sticker transform handles stay interactive. The optional right-hand sticker tray selects actual active project stickers and can be closed; it never inserts the reference's sample crown, text or scene. No keyframe-details or filename HUD covers the picture. Real project-clock transport, clip navigation, undo/redo and fullscreen remain below the preview. The prior selected-video **Keyframe** and **Animation** requirement remains above the timeline even though the locked illustration does not show that extra row.

The rejected always-visible clip toolbar is not part of the default locked editor. **More** reveals the real selected-clip actions, including Split, Trim, Speed, Volume and Keyframe where supported. The separate outlined bottom dock retains **Media, Audio, Text, Overlay, Stickers, FX, Filters, More** with white line-style icons. The illustration's mountain, Dream Big artwork, sample sticker contents, waveform shapes and fixed durations are not substituted for the owner's real project. Track count and preview content necessarily follow the opened project; waveform shapes require decoded source audio rather than fabricated fallback bars.

The primary dock is horizontally scrollable: **Media, Audio, Text, Overlay, Stickers, FX, Filters, More**. Media now opens the reachable project-media library, with real device Video/Photo/Audio import actions rather than fictional stock/cloud media. Audio imports phone audio; Overlay retains distinct image/video routes. Existing additional tools stay under More, with their existing project controllers. Camera/Lenses are removed from the editor; an external SDK camera capability elsewhere in the app is not part of this editing flow. Unsupported export scope is explained instead of claiming every timeline feature is exportable.

## Horizontal features, with the editor kept in view

**51341.png** describes the feature families, not permission to replace the locked 51303 editor with separate tall portrait screens. Color, Audio and Export now enter through the persistent editor route. Audio opens the real project mixer rather than the legacy illustrative Vocals/Beats/SFX screen. Keyframe and Speed use bounded horizontal control cards; sticker choices and project audio tracks scroll horizontally. Text, Trim, FX, Filters and Overlay panels are bounded below the preview; some related controls still scroll vertically inside a compact panel/card. This is not a claim that every legacy More tool has been fully converted to an exclusively horizontal layout.

Export settings use a horizontal card strip. The live preview players are released when this workspace opens, before encoding can start. The picture above these controls is explicitly labeled as a **source frame only**, not a fully rendered export-composition preview. Returning to editing recreates the normal players without deleting project data. The header's redundant resolution/export triggers are disabled in this workspace; its real settings, gated export, cancel and sharing actions are in the cards.

**Known exceptions:** Android media selectors, permission prompts and sharing use native system UI. The advanced legacy More tools have not all been migrated or device-proven. Do not report the owner's “every feature horizontal” request as completely satisfied while these exceptions remain. The separate SDK camera Activity is not exposed as an editor Camera/Lenses action.

## Real combined Color comparison

The Color controls keep the locked **51340** navy/cyan/purple visual language, with their controls arranged horizontally when embedded in the editor. Wheels, editable five-point R/G/B/luminance curves, brightness, contrast and saturation form **one deterministic SDR grade**. Before is the actual original bitmap/frame; After is that exact decoded frame processed with the current combined settings. The divider reveals the two full-size aligned images, not differently scaled halves or decorative gradients. Changes recompute the processed frame without changing the source. Video comparison is a paused, scrubbed frame comparison—not synchronized live video playback.

Standalone **selected-source** outputs remain available: a full-resolution graded PNG (up to 12 MP and 5000 px per side), or a whole-source H.264/AAC MP4 (verified SDR 8-bit sources, up to 3840 px per side, 30 minutes and 2 GB staging limit). This standalone choice deliberately does **not** apply project trim, speed, effects, overlays or timeline composition. Image/frame preview and video export use the same generated 33³ LUT with trilinear interpolation; this does not by itself prove device decoder/encoder color-management or lossy-codec pixel identity. HDR, unknown transfer and unverified pixel formats fail closed with a reason. No AI, prompts or generated replacement media are involved.

The owner's later approval also enabled **Export timeline with grade**. It snapshots the combined Color grade and passes it into the existing supported sequential composition route; each eligible rendered item receives the same grade after its supported foreground effects/text and before final output sizing. Trim, supported speed/keyframes/effects and supported audio postmix retain that route's existing behavior. Every main-video source must pass verified-SDR preflight. The route explicitly rejects unsupported content instead of dropping layers or effects; visible PiP, project-level stickers, boundary transitions and other composition limitations below still block it. New output files leave original media and saved project edits unchanged.

**Still incomplete: full-composition Before/After.** The Color comparison reads one selected source bitmap/frame, not the rendered project with all its layers. The existing composition builder lives in the export route; there is no shared playback/comparison surface for the complete composition. Safely completing this needs a reusable composition preview/player and device checks, not relabeling the source frame. Consequently this PR must not be described as complete full-timeline Color preview/export parity.

The Color header Export trigger opens this grade's export flow, never the unrelated project exporter. Original files/project clips remain untouched; outputs use new files. Native video cancellation targets only its own FFmpeg session and waits for completion before cleaning temporary input/LUT files. A completed output is retained if opening the sharing app fails, so Retry share does not encode again.

## Added controls and preservation checks

- Home adds access to real saved projects, rename and confirmed project-record deletion. No fabricated Cloud/Templates service or destructive media cleanup is substituted for missing capabilities.
- Keyframe Copy/Paste/Reset edits actual pins. Add captures interpolated transform/audio/effect values; paste preserves independent pin identity and is undoable.
- Animation exposes In/Out/Loop, duration and strength with explicit Apply to real keyframes. It is not an illustrative-only preset grid.
- Selected-sticker controls expose real opacity, range, size, rotation, shared-keyframe animation, duplicate and delete. No selected sticker means no misleading live properties.
- Filters preserve the original 12 looks and add 50 distinct authored parameter recipes: **62 offline looks** in All/Originals/Cinematic/Analog/Pastel/Urban/Nature categories. Strength, exposure, contrast and saturation use the shared preview/export shader path. Swatches are labeled decorative colors, not fake processed source thumbnails.
- VFX adds actual chromatic split, scan glitch, light leak, vignette and edge glow processing, using the selected source interval and strength rather than generated replacement media.
- Filter/FX drafts now invalidate the actual Player effect binding, including a same-position refresh for a paused ready player. Main-track-video scope remains explicit; unsupported overlay/photo combinations are not presented as working live effects.
- Text range controls and selected-layer handles edit the real absolute project interval. A logical title can span multiple main clips through clip-local segments; style edits, duplicate and delete operate on all its segments. Intro/loop/outro presets retain one continuous logical animation window across the cuts. New project-range segments use half-open windows; saved legacy captions retain their inclusive endpoint convention. Manual text no longer bypasses its real visibility window, and unrelated legacy clips with reused text IDs are not joined into a logical layer. **Manual transform or mask keyframes across those cuts remain unsupported:** the range card warns and timeline export blocks rather than silently changing that motion. Keep such a title within one clip or use preset text motion. Test clip-boundary motion as well as static text on the phone.

The host GLES harness compiles the exact production shader and checks all registered looks/effects, actual changed pixels, uniqueness, disabled/zero-strength identity, alpha and advanced controls. Its report is `scripts/workspace-shader-test-report.json`; it is host Mesa evidence, not an Android encoder/playback result. Public design references and verified licenses are recorded in [engineering source notes](editor-open-source-patterns.md); no third-party preset/code/assets were imported.

| Action | Project/preview behavior | Export behavior and honest limit |
|---|---|---|
| Main-clip navigation / seek / play | The project clock selects and binds the correct V1 source. Trimmed and speed-adjusted source seeks use `ClipTimeMapping`; stale source clocks cannot overwrite a cross-clip seek. | Sequential V1 export uses the same trim/speed model. Actual phone decoding, clip-boundary continuity and audio-tail behavior still need device checks. |
| Keyframes | The selected-video control mutates the actual track; the panel edits real project keyframes. Main preview uses project time. | Export maps clipped-source timestamps through trim, speed and project placement. Later-clip/trim/speed regression tests cover the clock; this is not a claim of device-render verification. |
| FX / Filters | Selecting a preset previews a draft. Apply commits the retained source range; Cancel discards the draft. | Supported ranged effects share the shader implementation with export. Invalid/unsupported ranges stop export rather than disappear. |
| Text / stickers / PiP | Existing panels mutate the project; overlays retain their gesture/keyframe controllers. Preview uses the active main clip's crop and text owner. | Selected-clip and whole-project export are different scopes. Project-level stickers, visible PiP and other unsupported composition edits explicitly block whole-project export. Do not interpret a successful selected-clip export as a complete-project export. |
| Audio | Phone picker and existing volume/trim/track controls retain real project mutations and live audio synchronization. | Canonical project music tracks use the supported postmix route. Legacy audio/SFX clips and unsupported timeline-audio configurations are rejected explicitly. |
| Boundary transitions | The chooser animates source endpoint thumbnails and saves the selected junction setting. | **Not end-to-end:** main timeline playback does not render boundary transitions, and whole-project export remains blocked. The panel and More explain this. This PR does not claim to implement that missing composition engine. |
| Enhance / ESPCN | Deterministic color presets are distinct from learned upscaling. Only existing project video is processed locally, without prompts, generation or cloud processing. | The same processed video URI is used by preview/export. The reported 02:59 source remains unsupported by the 00:30 whole-source ESPCN cap; trimming the timeline does not bypass it. Codec, dimensions, model and storage checks may also reject a source. |
| Missing media / Retry | Missing user media is no longer silently replaced or materialized as generated demo footage. Retry reloads the active project's actual URI at the actual project position. | Missing media must fail rather than export substituted footage. Existing media/project records are not deleted or migrated. Explicit demo/template identifiers remain separate. |
| Overlay Speed / Volume | Main-video Speed remains enabled. The misleading generic Speed action is omitted for overlays with an explanation; overlay Volume opens Properties and edits the real `overlayVolume` used by PiP playback. | Visible PiP still blocks whole-project export; this is not a new composition capability. |

Working clip operations remain; supported project audio tracks keep their own controls. | Legacy audio/SFX clips still block whole-project export rather than disappearing. |

Whole-project composition still has explicit limits beyond the rows above, including photos, masks, drawings, AR, certain per-clip GPU edits/background replacement and unsupported global effects. Its preflight messages are the authoritative current capability gate. These are known limitations, not newly completed features. The app must never silently drop them.

## Test the exact APK, preserving existing projects

1. Check the supplied provenance SHA against the PR head. Open Installed build from the branded header (or use Settings > About). If the installed app reports a signing conflict, stop and preserve the installation and projects; do not uninstall or clear app data.
2. Open the same existing 02:59 project from the device screenshots. Confirm a large undistorted preview, compact timeline, no SEC gutter, no eye controls, no dead black lane, and real 00:00 alignment. Test portrait and landscape, short and long projects, horizontal tool scrolling, timeline pinch/scroll/trim and focus mode.
3. Select a video: the keyframe control appears above the timeline. Add/edit/remove diamonds, deselect the video, and verify the control hides. Compare saved/reopened project state.
4. Use two differently trimmed clips, with a speed change on the second. Seek before/after the junction, use previous/next, and play across it without selecting the next clip. Verify source identity, audio and final position. Test music extending past V1 and seeking back out of that tail.
5. Apply each enabled FX/filter to a short range, cancel another draft, undo/redo and reopen the project. Export a supported scope and inspect the resulting file at times before, inside and after the range. Repeat for keyframe position, zoom, rotation, opacity and saturation on a later, trimmed, sped-up clip.
6. Verify text/sticker/PiP/audio changes in preview and the actual exported file in the supported scope. Try an unsupported whole-project configuration and confirm an explicit blocker, not a silently incomplete movie. Test transition disclosure and removal.
7. Confirm the 02:59 ESPCN input is accurately rejected without starting processing. For a supported short video, verify on-device processing, undo to the original URI, and matching processed preview/export. Do not expect optional AI weights or Camera Kit feature delivery to be proven by a lean local APK alone.
8. Rename or temporarily revoke access to a test source outside the app, then reload: an error must appear, never substituted sample footage. Restore access afterwards; do not delete the owner's media.
9. Open Color on an existing still and a verified SDR video. Drag all three wheels, edit R/G/B/L curves, combine the three sliders, and move the divider. Scrub the video and confirm Before/After always show the same scene/time. Export each supported source, inspect the actual output, cancel a video export, and retry sharing a completed output. Confirm original file hashes/project media URIs are unchanged. Unknown/HDR video and oversized stills must explain why processing is refused.
10. Open the core editing tools at 375×830-equivalent portrait size. Confirm the top video workspace remains visible, Close stays reachable, and horizontal cards/choices can be reached without switching into a tall standalone portrait workflow. Record the SDK/native-UI exceptions and any legacy More tool that remains too tall; these are not silently waived by a successful build.

Host/JVM tests, static APK alignment, host GLES pixels and a successful build are not physical-device tests, full exported-video parity proofs, Play delivery verification or Google Play approval. Record device model, Android version, exact build SHA and any failing action before approving a merge.
