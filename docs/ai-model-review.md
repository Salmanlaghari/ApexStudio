# Offline AI: what is available and what is still blocked

## Safety is fail-closed, not a completed classifier

There is **no app-validated offline classifier covering sexual, violent and hateful content**. The reviewed moderation-artifact catalog remains empty. `GlobalModerationEnforcement` denies new Whisper caption inference, English acoustic alignment, full-clip background replacement, gesture editing, face-reframe application and public ESPCN user-content upscaling. Caption/background failures explain that no protected processing ran. Review marks, model presence, arbitrary scores and caller approval booleans cannot grant authorization; there is no production override.

Manual captions, existing text editing, undo/clear/restore, ordinary editing/export, deterministic signal suggestions and explicitly informational offline analysis remain available. Low-level model-evaluation/instrumentation seams are not an approved user-content feature or a moderation result. Clearing an existing face crop remains an ordinary undoable edit.

The narrow [OwenElliott image-safety classifier candidate](https://huggingface.co/OwenElliott/image-safety-classifier-xs) has MIT-declared metadata and NSFL/NSFW/SFW outputs, but no hateful-content output. Its weights are not bundled and it cannot authorize protected actions. Publisher evaluations do not establish app-specific false-negative rates, calibration or contextual hate coverage. Future approval needs exact-byte provenance, preprocessing/label-policy semantics, representative independent evaluation and per-category threshold/recall evidence. Context and definitions matter in [hate-speech detection](https://pmc.ncbi.nlm.nih.gov/articles/PMC6701757/); a skin-color or pixel heuristic is not a substitute.

## Offline review reliability follow-up

Scene analysis now schedules only timestamps inside the retained source interval: the trim out-point is exclusive, even when it lies exactly on the sampling grid. A sample cap is spread across the entire retained interval, including its final millisecond, rather than dropping the tail. The bounded planner handles one-millisecond clips and long-safe arithmetic without first allocating a duration-sized list. These are requested decoder positions; `OPTION_CLOSEST` still chooses a nearby actual video frame, not a frame-accurate trim acceptance guarantee. Coroutine cancellation is checked around synchronous decode and before progress/results; it cannot interrupt a native decode already in flight.

Face and scene analysis share an explicit source policy rejecting direct network schemes, protocol-relative remote hosts and remote `file://` authorities before decoding. User-selected `content://` providers and app resource providers remain supported; a provider may itself access remote storage, so this is not a promise of device-wide network isolation.

The review sheet hides stale signal suggestions and face samples, including review/apply controls, when their captured project/source/edit snapshot no longer matches. It explains that re-analysis is required; controller-side stale-action rejection remains the final boundary. These improvements do not enable moderation-protected actions or finish missing model packs.

Manual overlay transforms now repair non-finite position, scale, rotation and opacity values in the edit surface, controller and keyframe insert/replace paths. Invalid updates retain a finite existing value or the normal default; rotation operands are reduced before addition to avoid overflow. An unchanged normalized trim returns without adding a misleading undo entry. These are regression-tested editing guards, not evidence of physical-device gesture/rendering acceptance.

## Manual crop and source-boundary follow-up

Crop now offers a horizontal manual control strip for Left, Top, Right, Bottom, Pan X and Pan Y, alongside the ten existing aspect presets. Edge controls keep the opposite edge anchored and retain at least one percent of the source. Panning preserves the window size and aspect. The draggable normalized-source diagram is a **draft geometry aid, not a live decoded video preview**. Apply commits once into the existing preview/export crop state; Cancel, disposal or a source/selection/project change discards the draft. The controller rechecks the captured clip and project before committing. New crop/reset changes have one undo entry; unchanged persisted geometry does not create another. Older photo-only crop edits are used as the draft's actual starting point.

The crop metadata reader runs off the UI thread, accounts for ordinary JPEG EXIF quarter-turns plus user photo rotation, and supports file paths as well as selected content URIs. Failed metadata no longer leaves a permanent “Reading” state or silently ignores all buttons: it explains the failure and offers Retry, while normalized Manual and full-frame Reset remain available. Aspect presets require valid source dimensions. Mirrored EXIF orientations retain the existing photo renderer policy; this is not a claim that mirrored EXIF rendering was fixed. Cancellation suppresses stale metadata delivery but cannot interrupt an in-flight native metadata call.

Reviewed signal-scene splitting now requires the raw trim bounds to equal the analyzed source interval and remain inside the source duration. A normalized analysis of malformed persisted trim bounds cannot authorize splitting beyond the source. Suggestion ordering is checked before subtraction, preventing extreme invalid timestamps from overflowing into split boundaries. These changes leave protected AI actions disabled. Local JVM/Compose tests are not phone, camera, GPU or export acceptance.

## Bundled assets and learned ESPCN upscaling

The lock file inventories **12 pinned entries totaling 216,670,511 bytes before APK compression**, including official MediaPipe face/pose/hand/segmentation assets, multilingual Whisper tiny int8, English wav2vec2 CTC alignment and a learned ESPCN super-resolution model. Token/config files count as inventory entries. Licenses and hashes accompany the assets; private materialized copies add storage. No cloud inference, paid API, automatic model download or network fallback is introduced.

The new [ESPCN asset notice](../app/src/main/assets/models/super_resolution/README.md) pins ONNX Model Zoo's Apache-2.0 `super-resolution-10.onnx`: 240,078 bytes, SHA-256 `85f36ff88cc504a24af5e0602148bc56a8aa09a58eca8c0da2756f3e8186035e`. It is a learned **x3 one-channel luminance** network, not RealESRGAN. The adapter verifies the bytes/schema, converts RGB to BT.601 YCbCr, runs fixed 224×224 luma tiles, stitches overlap ownership, bicubic-resizes chroma and returns exact x3 dimensions. Cache publication is verified/atomic; native tensors/results are closed and malformed/non-finite output is rejected.

`python3 scripts/smoke-espcn.py` runs actual host CPU inference on the deterministic image fixture. The Android instrumentation smoke uses an explicitly internal model-validation seam; the public `upscale` method remains globally gated. Host inference and compiling device tests do not establish Android execution, quality/latency, image-model approval or moderation. Output is capped at 4,194,304 pixels, so this is **not** a 1080p/4K editor/export pipeline and does not implement exact 720p→1080p conversion. Alpha is reconstructed as opaque; transparent-image preservation is not implemented.

The generic RGB ONNX background-removal/upscale/style adapters still require a task-specific reviewed artifact manifest whose exact digest is in the code-reviewed image-model catalog. That generic catalog remains empty; the dedicated pinned ESPCN evaluation backend is not a way to self-approve an arbitrary ONNX file.

## Face-reframe and gesture plumbing

Face review uses real decoded samples and bundled landmarks. It offers horizontal 9:16, 1:1 and 16:9 review targets; changing target clears review marks without editing the clip. Sampling can miss brief faces/fast motion, temporary IoU IDs are not identity recognition, and fallback crops are not detections. At least one actual detected face, every sample reviewed and an unchanged project/source/trim/speed snapshot are required before the apply boundary—**which currently denies on moderation**.

A validated, serializable source-time `FaceCropTrack` now stores aspect-consistent keyframes. Lookup clamps/interpolates measured geometry. Preview and export have a dynamic Media3 shader path; preview uses source-absolute PTS, while export inserts crop before speed effects and adds the source trim offset to clipped-source PTS. Speed is not applied twice or numerically inverted to recover a crop. This follows the [Media3 1.5 decoder timestamp rebasing](https://github.com/androidx/media/blob/1.5.0/libraries/transformer/src/main/java/androidx/media3/transformer/ExoAssetLoaderVideoRenderer.java); [speed effects subsequently change PTS](https://github.com/androidx/media/blob/1.5.0/libraries/effect/src/main/java/androidx/media3/effect/SpeedChangeShaderProgram.java). Pure tests verify clock selection and long-safe arithmetic, not actual GPU/codec parity.

Manual crop/reset replaces rather than stacks an old dynamic crop. URI replacement, physical source-trim output, background replacement/restore and source repair clear stale face tracks. Ordinary trim/speed edits retain absolute-source geometry. Undo retains the original clip snapshot. Device-rendered tracking/reframe acceptance remains incomplete; this is not a promise that every face stays in frame.

The AI panel now reaches a CameraX gesture sheet. Explicit arming binds an unguessable session to the exact project/selected source. One-hand MediaPipe samples feed temporal debounce, swipe latching, pinch hysteresis and bounded source-edge trim/timeline-zoom planning. Stale/forged sessions, malformed values, lost/ambiguous tracking, pause/dispose and permission loss cannot silently retarget an edit. Camera permission, model startup and command delivery all independently check the global gate. **The current build intentionally cannot prompt for camera permission or start live gesture editing while moderation is unavailable.** This is wired infrastructure, not device-accepted functionality.

## English acoustic captions

The [English alignment asset notice](../app/src/main/assets/models/alignment/NOTICE.md) documents the pinned Apache-2.0 wav2vec2-base-960h quantized model and exact preprocessing. Text → Captions retains phrase, word-by-word and full-phrase karaoke modes. The English backend uses real local PCM, actual CTC emissions and Viterbi forced alignment—not equally divided phrase durations. Highlight ranges, genuine silence gaps, source fingerprints and speed-aware overlay preview/export/persistence are implemented. New transcription/alignment is now globally blocked; existing editable captions are retained.

Alignment rejects unsupported vocabulary/digits, invalid/overlapping intervals, ambiguous phrase mapping, corrupt weights/tensors and low-confidence/no-path results. Windows are bounded to 15 seconds with context and phrases to 14.4 seconds; whole-audio extraction remains capped at 30 minutes and retains PCM in memory. The 0.08 confidence floors are engineering heuristics, not calibrated accuracy guarantees. A selected content provider may itself access remote storage, but the app adds no HTTP inference/download/upload fallback.

The natural LibriSpeech host-inference fixture and real-emission JVM regressions are reproducible with `scripts/verify-english-aligner.py`; recognition errors are retained, not hidden. Device latency/RAM, noisy/accent accuracy, exact preview/export rendering and multilingual word alignment remain unvalidated. Urdu/Hindi remain phrase-timed, not measured word karaoke.

## Remaining model and release gaps

Learned TFLite Smart Trim, scene/style models and subject-aware crop packs are not supplied; the usable signal suggestions are explicitly deterministic heuristics. Artistic ONNX transfer and a suitable reviewed ONNX background-removal pack remain absent. [BRIA RMBG-1.4](https://huggingface.co/briaai/RMBG-1.4) has non-commercial weight terms, while [withoutBG's routed bundle](https://huggingface.co/withoutbg/withoutbg-openweights-onnx) is large and includes third-party terms; neither is bundled. [Real-ESRGAN upstream](https://github.com/xinntao/Real-ESRGAN) is not implemented by relabeling ESPCN or ordinary resizing.

Full-clip face privacy, pose effects, complete real-time model preview/export, calibrated all-category moderation and physical-device acceptance are still release blockers. Native inference is synchronous: coroutine cancellation discards stale results and cleanup waits for native work; it does not forcibly interrupt an already-running native call. Memory/lifecycle tests and compilable code are not evidence of model accuracy or a finished offline AI product.
